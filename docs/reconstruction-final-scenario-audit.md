# 「暮らしの再建」最終シナリオ監査

実施日: 2026-08-12
対象: 本番導線と `main` の静的HTML/CSS/JavaScript、公開用公式情報データ
注意: これは開発者による構造・動作監査であり、実利用者の理解を証明するものではない。

## 総合判定

P0は0件。P1を1件検出し修正した。修正後は、3シナリオとも制度対象判定を行わず、困りごとの整理から自治体等の公式情報へ到達できる構造である。現時点で本番運用に耐えられる。ただし70代利用者の理解・スクロール負担はA-01、B-01、C-01の実利用者テストで継続確認する。

## SCENARIO A — 70代・宇土市

### トップからの導線

トップの「暮らしの再建」は支援情報ポータルと並ぶ主要カードとして表示される。暮らしの再建では主要CTAが3つに限定され、制度名を知らなくても「困りごとから探す」を選べる。

### 住まい

「住まい」カードは「家に住めない・家を直したい」と日常語で表示される。宇土市を選択した場合だけ `uto-housing.html` を表示し、他自治体では除外する。専用ページには宇土市公式ページへの直接リンクと発表主体がある。

### 断水・給水

宇土市の `daily_life` に「給水車による給水」「水道の復旧状況」等の日付付き公式情報がある。カードは宇土市公式と発表日を表示する。古い情報を「現在も有効」と断定する文言はない。

### 健康・介護

宇土市住まいページから、自治体を維持したまま健康・介護へ進む導線を追加した。健康ページは診断や緊急度判定を行わず、医療・保健・介護の自治体公式情報を絞り込む。

### 操作数

- トップ → 暮らしの再建 → 住まい → 宇土市専用情報: 約3操作
- 宇土市専用情報 → 水道・移動 → 公式リンク: 追加2操作程度
- 宇土市専用情報 → 健康・介護 → 公式リンク: 追加2〜3操作程度

### 高齢者UX

主要文字は16px以上、操作領域は48px以上、スマートフォンでは1列になる。アイコンだけでなく文字を併記する。長い宇土市住まいページは見出しとページ内リンクで分割されるが、実利用者によるスクロール負担の確認は必要。

### 問題

P1: 宇土市住まいページから暮らし・移動／健康・介護へ直接戻れなかった。自治体を保持する3つの関連導線を追加して解消した。

## SCENARIO B — 子育て世帯・宇城市

### 暮らし整理ナビ・複数課題

「何から始めればいいか分からない」から、住まい、お金、子ども、仕事、証明を複数選択できる。結果は「診断結果」「おすすめ」ではなく、「気になるところから、一つずつ確認できます」と表示する。

### 自治体引き継ぎ

検証自治体は宇城市。`municipality_uki` はカテゴリページ、関連カテゴリ、公式情報ナビへクエリで引き継ぐ。自治体切替時は同じ描画関数が結果を置換するため、前自治体のカードを残さない。

### 各分野

公開データ上、宇城市には住まい4件、お金3件、仕事2件、子ども2件、証明5件の表示候補がある。各カードは宇城市公式URLへ直接進む。宇土市以外では `uto-housing.html` を除外する。

必要書類や期限は未確認状態から断定せず、公式ページでの確認を促す。

### 確認メモ

5つの選択を簡潔に一覧化できる。冒頭で「診断結果、申請書、行政の公式書類ではありません」と明示し、A4印刷CSSを持つ。選択内容は保存しない。

### 操作数

トップ → 暮らしの再建 → 整理ナビ → 5項目選択・整理 → 分野 → 自治体選択・公式情報で、おおむね5〜6操作。自治体が事前選択済みの場合は4〜5操作。数字だけを減らすための自動判定は追加しない。

### 問題

P0/P1なし。5課題選択時は結果量が増えるため、実利用者テストで「全部確認しなければ」と感じないか確認する。

## SCENARIO C — 地域支援者

### 支援者入口・困りごと整理

支援者ページと暮らしの再建ページに「相談を受けている方へ」がある。制度対象を判定するものではないと明記し、住まい・お金・健康を複数課題として整理できる。

### 住まい・お金・介護

各分野から自治体公式情報へ進める。アクションは一般案内1件と、確認済みの制度固有項目を合わせて最大3件に制限する。

### 総合相談fallback

分野を選べない場合は、自治体等の総合相談・自治体災害関連公式情報へ進む。よか隊ネット熊本の問い合わせはfallbackにしていない。

### 対象判定誤認・個人情報

所得、病歴、借入、家族関係の詳細入力欄はない。「対象外」と支援者が判断する出力もない。公式情報で判断できない場合は公的窓口へ戻す。

### 確認メモ・操作数

本人と一緒に確認できる短い一覧で、行政書類ではないことを明示する。支援者ページから公式情報まで約4〜5操作。

### 問題

P0/P1なし。折りたたんだ支援者向け入口の発見率はC-01で確認する。

## 共通結果

- 主導線: 3CTA。目的の近い入口は重複しない。
- 8カテゴリ: 制度名ではなく困りごとの日常語で選べる。
- 自治体選択: 21市町村。selectは十分な高さを持つ。
- municipality継承: 許可リストで検証し、カテゴリ・関連導線へ引き継ぐ。
- 公式情報: 市町村名、公式、発表日、公式URLを表示する。
- fallback: 0件・読込失敗でも支援不存在と断定せず自治体公式へ進む。
- 行政誤認防止: よか隊ネット熊本が整理していること、公的機関で最終確認することを表示。
- 中立性: よか隊ネットへの相談獲得を主要fallbackにしない。
- 次に確認すること: 最大3件。
- 検索: 明確な言葉から公式情報へ進め、0件でも支援不存在としない。
- 戻る導線: 暮らしトップと選び直しを分離。
- 行き止まり: 未選択、0件、読込失敗、JS無効の全状態に代替導線がある。
- 情報量: トップ主要CTA3、カテゴリ8、公式情報初期最大5。
- モバイル: 320/375/390/430px向けCSSと1列化を確認。
- 200% zoom: 相当表示で主要導線に横スクロールなし。
- キーボード: DOM順と視覚順が一致。button/select/detailsはTab、Enter、Spaceで操作可能。
- JavaScript無効: 静的8カテゴリ、市町村公式一覧、公式fallbackを維持。
- 個人情報: 氏名・住所・病歴・所得・借入・家族詳細の入力なし。
- Storage: localStorage、sessionStorage、cookie不使用。
- Analytics: 困りごと・検索語をgtag/dataLayerへ送らない。
- 印刷: 確認メモにA4・白黒・長URL対応の印刷CSSがある。
