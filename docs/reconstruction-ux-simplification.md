# 「暮らしの再建」UX統合・簡素化レポート

更新日: 2026-08-12

## 結論

トップの主要入口を4つから3つへ整理し、8カテゴリを「困りごとから探す」の配下に明確化した。確認メモ、アクションナビ、支援者向け表示は主要入口から外し、選択後または補助導線として維持する。新機能や依存ライブラリは追加していない。

## 現在の主要機能と役割

- 暮らしの再建トップ: 被災後の困りごとを選ぶ入口。
- 8カテゴリ: 住まい、お金、証明、健康、家族、仕事、農漁、日常生活の入口。
- 暮らし整理ナビ: 何から始めるか分からない人が複数の困りごとを整理する補助機能。
- 自治体選択: 選択した自治体をカテゴリ・公式情報へ引き継ぐ機能。
- 自治体公式情報: 選んだ分野について市町村の一次情報へ進む導線。
- 公式情報検索: 探したい言葉が分かる人が公式情報を直接探す機能。
- 関連カテゴリ: 同時に起こりやすい別の困りごとを2〜4件だけ示す補助導線。
- アクションナビ: 選択後に「次に確認すること」を最大3件示す機能。
- 確認メモ: 選択後の内容を印刷・共有する任意機能。
- 支援者向け表示: 相談を受ける人向けの補足を折りたたんで示す導線。
- 確認済み制度情報: 公開条件を満たす制度だけをアクション等へ使うデータ。

## 主導線と情報階層

主要入口は次の3つだけとした。

1. 困りごとから探す
2. 何から始めればいいか分からない
3. 公式情報を言葉から探す

「相談したい」は主要CTAから外し、ページ後半の公的機関案内で扱う。8カテゴリは1の配下、暮らし整理ナビは2、検索は3に対応する。確認メモとアクションナビは選択後だけに現れる。

トップから「構築中」の長い注意枠、重複する補助CTA群、災害ケースマネジメント説明を外した。運営主体と更新中の説明はページ末尾に短く残した。

## カテゴリ・公式情報・関連情報

- 8カテゴリの順序は、生活への即時影響と既存利用者の学習を考慮して維持した。
- カードはアイコン、カテゴリ名、補足1行に統一した。
- 内部値（home、money、verificationStatus等）は表示しない。
- 自治体公式情報は初期5件までで、残りは展開する。
- 検索結果は公式サイトへ直接進み、独自詳細ページを増やさない。
- 関連カテゴリは設定データで2〜4件に制限済み。

## 戻る導線・状態・免責

- サービストップへの復帰は「暮らしの再建」、再選択は「選び直す／ほかの困りごと」に役割を分ける。
- パンくずはホーム、暮らしの再建、カテゴリを基本とする。
- 古い「準備中」を4カテゴリから削除した。
- `verificationStatus`、`freshnessStatus`、`confidence` は利用者へ露出しない。
- 日付は日々変わる公式情報では表示し、恒久制度の取得日時を強調しない。
- 行政誤認防止と公式確認の注意は短文で残し、各ページ冒頭に長文を置かない。

## REMOVE / MERGE / KEEP / OPTIONAL

### REMOVE

- トップHeroの「とにかく誰かに相談したい」CTA
- Hero下の長い構築中注意枠
- 重複していた補助CTAカード2枚
- トップの災害ケースマネジメント説明
- 完成済みカテゴリに残っていた「準備中」表現
- カテゴリカードの第3階層説明

### MERGE

- 「相談したい」は専門機関・公的機関案内へ統合。
- 構築中・運営主体・公式確認の注意はページ末尾の「このページについて」へ統合。
- 「相談メモ」の利用者向け名称は「確認メモ」へ統一。

### KEEP

- 8カテゴリ
- 暮らし整理ナビ
- 自治体選択とmunicipality引き継ぎ
- 自治体公式情報と0件fallback
- 公式情報検索
- JavaScript無効時の静的導線
- 選択後のアクションナビ

### OPTIONAL

- 確認メモ
- 検索例
- 折りたたんだ支援者向け説明
- アクション確認チェック

今後の実利用者テストで、発見率と理解度が低い場合に再評価する。

## CSS・JavaScript・dead code

共通のカテゴリ関係、自治体選択、公式情報描画は既存共通JSを維持した。トップから削除した位置づけ枠・補助カード・ケース説明の主要CSSを削除した。万能コンポーネント化や新規ライブラリ追加は行っていない。旧クラス名の一部は共有セレクタと印刷互換のため残しており、視覚表示には使われない。

## モバイル・高齢者・アクセシビリティ

- 320、375、390、430pxを想定した1列配置と48px以上の操作領域を維持。
- 200%ズームでも主要導線が横スクロールにならない設計。
- アイコンだけで意味を伝えず、必ず文字ラベルを併記。
- 見出し順、DOM順、Tab順を一致させ、`:focus-visible`を維持。
- 支援者向け補足は標準の`details/summary`でキーボード操作可能。
- `prefers-reduced-motion`、印刷、noscript fallbackを維持。

## パフォーマンスと障害時

静的HTML/CSS/JavaScriptの構成を維持し、依存ライブラリは追加していない。検索データは検索実行時だけ読み込む。検索・確認メモ・アクションナビが失敗しても、静的8カテゴリと自治体公式fallbackは残る。選択内容・検索語はStorageへ保存せず、Analyticsへ送信しない。

## ページ統合候補

現時点で削除・統合すべき公開URLはない。`reconstruction-official.html`はカテゴリ共通の公式情報表示、`reconstruction-search.html`は言葉検索で役割が異なるため維持する。外部共有済みURLは変更しない。

## 実利用者テストで確認すること

- 5秒以内に「被災後の困りごとから探すページ」と理解できるか。
- 3入口の違いを説明なしで選べるか。
- 8カテゴリの補足1行だけで迷わず選べるか。
- 支援者向け折りたたみを必要な人が発見できるか。
- 「確認メモ」という名称で用途を理解できるか。
- 高齢者が375px相当・200%ズーム・キーボードで公式情報まで到達できるか。

次の開発は新機能追加ではなく、実利用者テストで上記を確認し、OPTIONAL項目の維持・削除を判断する。
